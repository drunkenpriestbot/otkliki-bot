# Передача: бот-мониторинг заказов + автогенерация откликов (под Telegram)

Это не готовый к запуску бот, а рабочая архитектура и реальный код из похожего
проекта (мониторинг биржи Kwork → черновики откликов → Telegram), адаптированные
под то, что источник заказов теперь — Telegram-каналы/чаты, а не веб-биржа.
Личные данные (профиль, портфолио, бренд, токены) полностью вычищены — оставлена
только архитектура, рабочий код и накопленные методом проб и ошибок решения.

Claude, который это получил: прочти `LESSONS_LEARNED.md` ПЕРВЫМ — там собраны
конкретные грабли, на которые уже наступали при сборке точно такого же пайплайна,
чтобы не наступать на них снова.

## Архитектура (4 шага, раз в N минут через GitHub Actions)

```
monitor_telegram.py → classify.py → draft.py → notify.py
   (источник)         (дёшево/    (дорого/точно:   (Telegram-
                        быстро:     Claude пишет     уведомление
                        Groq        черновик          + кнопка)
                        фильтр)     отклика)
```

1. **monitor_telegram.py** — читает новые сообщения из Telegram-каналов/чатов
   с заказами, отсеивает уже виденные (`seen.json`). **Это скетч, не проверенный
   живой код** — в оригинале источником была веб-страница (Kwork), здесь логику
   парсинга нужно написать под конкретные каналы. См. раздел "Как адаптировать"
   ниже — там два рабочих способа подключиться к Telegram как источнику.
2. **classify.py** — бесплатный грубый фильтр через Groq API (быстро, без лимитов
   Pro-подписки) — отсекает явно нерелевантное до того, как тратить дорогой вызов
   Claude. Готовый рабочий код, поменять нужно только текст `PROMPT_TEMPLATE` —
   описание того, что считается релевантным заказом в твоей нише.
3. **draft.py** — финальная проверка релевантности + написание черновика отклика
   через `claude -p` (CLI на Pro-подписке, без отдельной платной оплаты API).
   Готовый рабочий код. Внутри — `BRIEF`/`PORTFOLIO`/`SALES_PRINCIPLES`/
   `WRITING_RULES`: первые два — пустые шаблоны под твои данные, вторые два —
   реальная вынесенная методика, как писать продающий холодный отклик (см.
   `writing-otkliki-skill.md` — то же самое отдельным файлом, если нужно
   применять не только в этом боте).
4. **notify.py** — шлёт в Telegram уведомление с заголовком/бюджетом/ссылкой
   и черновиком отклика в виде блока, который копируется одним тапом. Готовый
   рабочий код, ничего менять не нужно (источник заказов уже был Telegram,
   этот шаг переносится без изменений).

Плюс `cloudflare-worker/` — отдельный бесплатный вебхук, который подхватывает
твой Reply на сообщение бота (если ты отредактировал черновик) и прикрепляет
такую же кнопку "Перейти к заказу" к твоему отредактированному сообщению.
Готовый рабочий код, не требует изменений.

## Как адаптировать monitor_telegram.py под реальные каналы

Два рабочих способа читать сообщения из Telegram-каналов программно:

- **Bot API (`python-telegram-bot` / `requests` к `api.telegram.org`)** — работает
  только если твой бот ДОБАВЛЕН АДМИНОМ в канал/чат (или это канал, куда бот может
  зайти как подписчик через `getUpdates`). Просто и без второго аккаунта, но не
  читает каналы, куда бота не добавили.
- **MTProto-клиент от имени пользователя (`Telethon` / `Pyrogram`)** — логинится
  твоим личным Telegram-аккаунтом (или отдельным, специально для бота) и читает
  ЛЮБОЙ публичный канал, на который подписан этот аккаунт, без необходимости
  добавлять бота туда. Чуть сложнее в настройке (нужен `api_id`/`api_hash` с
  my.telegram.org и первый интерактивный логин для сохранения session-файла),
  но это то, что реально нужно для мониторинга чужих каналов с заказами.

Для биржи фриланса в Telegram (где заказы публикуются в открытых каналах) —
нужен второй вариант (Telethon). В `monitor_telegram.py` оставлен скелет именно
под Telethon с комментариями, что нужно подставить.

## Секреты, которые понадобятся (репозиторий GitHub → Settings → Secrets)
- `TELEGRAM_BOT_TOKEN` — токен бота-уведомителя (через @BotFather)
- `TELEGRAM_CHAT_ID` — твой личный chat_id (узнать через @userinfobot или похожий бот)
- `TELEGRAM_SESSION` — строка сессии Telethon (генерируется один раз локально,
  см. комментарий в `monitor_telegram.py`), если читаешь каналы от имени аккаунта
- `CLAUDE_CODE_OAUTH_TOKEN` — генерируется локально `claude setup-token`, тратит
  лимиты твоей Pro-подписки, не отдельная оплата API
- `GROQ_API_KEY` — бесплатный ключ с console.groq.com, без карты
